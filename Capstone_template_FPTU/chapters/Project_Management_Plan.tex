\subsection{Communication Plan}
To maintain continuous alignment and prevent delivery bottlenecks, the team established a structured communication protocol:
\begin{itemize}
    \item \textbf{Daily Standups (Async / 15 mins):} Conducted via Discord/Slack to report: (1) completed tasks in the last 24 hours, (2) current objectives, and (3) technical blockers.
    \item \textbf{Weekly Sprint Review \& Planning (1 hour):} Formal weekly sync with the Academic Supervisor to review training logs, validation metrics, ablation graphs, and upcoming milestones.
    \item \textbf{Version Control \& Code Reviews:} Centralized GitHub repository utilizing protected branches. All pull requests require passing automated \texttt{pytest} suites and approval before merging.
    \item \textbf{Artifact \& Benchmark Repository:} Centralized synchronization of model checkpoints, vocabulary mappings, and evaluation JSON reports across Kaggle and local environments.
\end{itemize}

\subsection{Quality Management}
To ensure academic rigor, software robustness, and deterministic scientific reproducibility:
\begin{itemize}
    \item \textbf{Deterministic Seeds:} All dataset generators, tokenizers, weight initializations, and data loaders are locked with seed \texttt{42}.
    \item \textbf{Automated Test Suite:} Implementation of automated unit tests (\texttt{pytest}) verifying loss convergence, tensor shapes, gradient flows, and inference boundaries.
    \item \textbf{3-Tier Hierarchical Validation:} All candidate models must be evaluated against Character-level (\ac{CER}, \ac{BF1}), Word-level (\ac{WER}, \ac{WAcc}), and Sentence-level (\ac{EM}, Near-Perfect $\le 5\%$, \ac{BLEU}-4, \ac{ROUGE}-L) metrics.
    \item \textbf{Zero Test Contamination:} The 159,172 external \textit{the\_thao (Sports)} sentences are completely isolated from training and validation splits to guarantee fair out-of-distribution evaluation.
\end{itemize}

\subsection{Budget and Funding (Optional)}
The NextKey project was developed under an open-source, zero-financial-capital constraint by maximizing public cloud and institutional compute tiers:
\begin{itemize}
    \item \textbf{Compute Hardware:} Kaggle Dual Tesla T4 GPUs (30 hours/week allocation) and local Apple Silicon M-series workstations for rapid prototyping.
    \item \textbf{Software Stack:} 100\% open-source technologies (PyTorch, Hugging Face ecosystem, FastAPI, Streamlit, Git).
    \item \textbf{Total Direct Financial Cost:} \$0.00 USD.
\end{itemize}

\subsection{Change Management Process}
To accommodate necessary technical pivots without compromising deadlines:
\begin{enumerate}
    \item \textbf{Gate 1 (Smoke Test Gate):} Any candidate architecture unable to achieve sub-$1.0\text{ ms}$ latency or showing gradient instability during initial 1,000 steps is automatically disqualified.
    \item \textbf{Gate 2 (Benchmark Gate):} Model selection must be driven exclusively by objective held-out \ac{CER} and \ac{WER} metrics rather than subjective preferences.
    \item \textbf{Scope Kill Criteria:} Optional P2 tasks (e.g., complex multi-user online adaptation) are deferred immediately if core P0 multi-task restoration metrics fail to meet acceptance thresholds.
\end{enumerate}

\subsection{Closure and Evaluation}
Upon completion of Phase 4 training and evaluation:
\begin{itemize}
    \item \textbf{Artifact Handover:} All quantized checkpoints (\texttt{student\_ptq\_compact.pt}, \texttt{cascade\_tri\_bigru\_sota.pt}), vocabulary mappings, and evaluation JSONs are archived with SHA-256 checksums.
    \item \textbf{Codebase Packaging:} Complete containerized deployment instructions provided in the project repository for immediate academic replication and defense demonstration.
\end{itemize}
